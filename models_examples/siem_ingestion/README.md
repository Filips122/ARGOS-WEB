# SIEM Ingestion For Production Pipeline Events

This folder contains example ingestion artifacts for JSONL events generated by the production ML pipeline.

## Event Source

Events are written by the inference adapters under:

```text
src/models/PRODUCTION_PIPELINE/inference_runs/*/*/*_events.jsonl
```

Each line is a standalone JSON event with ECS-like fields such as `@timestamp`, `event`, `ml`, `rule`, `labels`, `related` and `entity`.

## Elastic/Filebeat Example

1. Review `filebeat.production_pipeline.example.yml` and set `TFM_REPO_PATH` to the repository root.
2. Load or adapt `elastic_index_template.production_pipeline.json` for the target index pattern.
3. Start Filebeat with the example config in a lab environment.

Example PowerShell invocation:

```powershell
$env:TFM_REPO_PATH = "D:/TFM/GIT/TFM_SIEM_IDS-IPS_IA"
filebeat.exe -e -c src/models/PRODUCTION_PIPELINE/siem_ingestion/filebeat.production_pipeline.example.yml
```

The default target index pattern is:

```text
siem-ml-production-alerts-*
```

## Operational Policy

Use SIEM rules to avoid turning every weak signal into an incident:

- Deduplicate by `ml.model_id`, `entity.id`, `event.dataset` and a short time window.
- Treat `ml.risk_score >= 90` as high confidence only when model status is production candidate or stronger.
- Use lower severities as enrichment signals unless correlated with IDS, authentication or asset criticality context.
- Rate-limit noisy entities before creating analyst-facing incidents.
- Keep `ml.policy_path` and `labels.production_status` for auditability.

The baseline SOC policy is versioned at:

```text
src/models/PRODUCTION_PIPELINE/policies/soc_alert_policy.production.json
```
